↓ same thing in SQL
CREATE TABLE reviews (id INTEGER PRIMARY KEY, item_id INTEGER REFERENCES menu(id), stars INTEGER NOT NULL, comment TEXT);
The one thing to remember

Every column is: name, kind, rules

Making a table is like designing a paper form. Every box on the form gets a label, says what kind of answer goes in it (“numbers only”), and may have rules (“must be filled in”). In SQL each column is written in exactly that order.

Kinds of data

Three kinds cover almost everything

The kind tells the database what can go in a column. It refuses anything else, so a typo like stars = 'five' can't sneak in.

INTEGER Whole numbers 1 42 310 -3

For ids, stars, calories, anything you count. 4.5 does not fit.

DECIMAL Numbers with a point 3.50 2.8 0.99

For prices and measurements. DECIMAL(5,2) means up to 5 digits, 2 of them after the point.

TEXT Words 'Lovely and hot'

For names and comments. Written in quotes when you add data.

Other names you will meet: different databases use slightly different words for the same ideas. INT means INTEGER. VARCHAR(100) is text with a maximum length of 100 characters (letters, digits, spaces and so on). NUMERIC and REAL are close cousins of DECIMAL. The playground understands all of these.
Rules

Rules the database checks for you

Rules come after the kind. You can give a column no rules, one rule, or several. Every time a row is added or changed, the database checks them and refuses anything that breaks one.

RuleSay it asExampleWhat it promises
PRIMARY KEY“each row's own key”id INTEGER PRIMARY KEYNever empty, never repeated. One per table, usually the id. You met this in Lesson 6.
NOT NULL“must be filled in”stars INTEGER NOT NULLA row without a value here is refused.
DEFAULT“if left out, use…”points INTEGER DEFAULT 0When INSERT leaves the column out, this value is used instead of empty.
UNIQUE“no two the same”email TEXT UNIQUETwo rows can't share a value, but the column may be empty.
REFERENCES“must match a row in…”item_id INTEGER REFERENCES menu(id)The foreign key from Lesson 6: the value must exist in the other table.
Why bother with rules? Without them, mistakes slip in quietly: a review with no stars, two customers with the same id, an order for an item that doesn't exist. Rules stop bad data at the door, so every SELECT you write later can trust the table.
The biggest eraser

DROP TABLE removes everything

DROP TABLE removes the whole table: every row, every column, and the table itself.

It is even bigger than DELETE without WHERE, which at least leaves the empty table behind. DROP TABLE reviews is fine for a practice table you made by mistake, but in a real database please double check the name first, because there is usually no Undo.

The database protects links here too: while orders REFERENCES menu, it refuses to drop menu. The playground also asks you to confirm every DROP.
